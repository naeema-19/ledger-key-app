# Ledger & Key

Rental property management portal for a landlord managing 5–6 homes.
Real Supabase Auth (email + password), Postgres backend, Row Level Security —
no Lovable AI credits required to build or run this.

## 1. Create a Supabase project
1. Go to [supabase.com](https://supabase.com) → New project.
2. Name it, set a database password (save it), pick a region, create.
3. Once provisioned, go to **Project Settings → API** and copy:
   - **Project URL**
   - **anon public** key (never use the `service_role` key in this app)

## 2. Run the database migration
1. In Supabase, open **SQL Editor → New query**.
2. Paste the entire contents of `supabase/migrations/0001_init.sql`.
3. Run it. This creates all tables, the owner/tenant role trigger, and every
   Row Level Security policy.

## 3. Configure the app
```bash
cp .env.example .env
```
Fill in your `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.

## 4. Install & run
```bash
npm install
npm run dev
```
Open the local URL it prints (usually http://localhost:5173).

## 5. Create your Owner account
Sign up in the app with your own email. The **first person ever to sign up
becomes Owner automatically** (see the `handle_new_user` trigger in the
migration). Every signup after that defaults to a Tenant role.

## 6. Add tenants
From the Owner dashboard → Tenants → Add tenant, enter their **exact email
address**. When that person signs up in the app using the same email, a
database trigger links their account to that tenant record automatically —
no invite emails or shared passcodes needed.

> If a tenant already had an account before you added their row, run
> `select public.relink_tenant_profiles();` once in the SQL Editor to link
> them retroactively.

## 7. Deploy
This is a plain Vite app — deploy the `dist/` folder (after `npm run build`)
to Vercel, Netlify, Cloudflare Pages, or any static host. Set the same two
environment variables on your host as you did locally.

### Optional: import into Lovable without spending generation credits
Push this folder to a GitHub repo, then in Lovable choose **"Import from
GitHub"** rather than prompting from scratch. Lovable will load the existing
code as-is; you'll only spend credits if you then ask it to *change*
something.

## What's built
- Email/password auth for both roles via Supabase Auth
- Owner dashboard: Overview, Properties, Tenants, Payments (auto-generated
  monthly dues, mark-as-paid, per-tenant filter, printable ledger export),
  Maintenance, Documents
- Tenant dashboard: their property + rent, full payment history with a
  printable ledger export, submit/view maintenance requests, shared documents
- Row Level Security enforced at the database level — tenants can only ever
  read their own data, even if the frontend were compromised
- Not intended for sensitive financial data (e.g. bank account numbers) —
  documents are text notes only, no file uploads

## Notes & things worth double-checking
- RLS policies use `security definer` helper functions (`is_owner()`,
  `current_tenant_id()`) to avoid recursive policy lookups — read through
  `0001_init.sql` before relying on it for real tenant data.
- Supabase's default email confirmation setting may require tenants to
  confirm their email before they can sign in — check **Authentication →
  Providers → Email** in your Supabase dashboard if signups seem stuck.
- This app was built by hand (not generated by Lovable's AI) specifically to
  avoid burning credits — review it like you would any code before trusting
  it with real tenant/payment data.
